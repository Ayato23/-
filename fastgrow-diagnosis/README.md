# FastGrow 採用ブランディング診断

10問の設問と企業HPの自動分析から、採用ブランディングの課題を5つの観点で診断し、
FastGrow のメディア活用（記事・露出・二次活用）の提案と無料相談の申し込みにつなげる診断型コンテンツです。

## 診断の流れ

1. **企業情報の入力**：会社名・HPのURL（任意）・フェーズ・採用したい人材・採用予定人数
2. **10問の設問**：5観点 × 2問、各4択（0〜3点）
3. **HP分析**（URL入力時）：トップページと、そこからリンクされた採用ページ・会社情報ページを取得し、15項目のシグナルを検出
4. **AIによる総評**（APIキー設定時）：回答とHP本文から、候補者視点の印象・課題・記事企画案を生成
5. **結果表示**：総合スコア／ランク（S〜D）／診断タイプ／レーダーチャート／優先課題／HPチェック結果／FastGrowを活用した解決策
6. **リード獲得**：無料フィードバックの申し込みフォーム → `data/leads.jsonl` に保存（Webhook通知も可）

### 5つの観点

| ID | 観点 | 設問で聞くこと | HPで見ること |
|---|---|---|---|
| vision | ビジョン・事業ストーリー | MVVを語れるか／勝ち筋を発信しているか | MVV、代表メッセージ、市場・事業の成長ストーリー |
| leader | 経営者・リーダーの発信力 | 外部メディア露出回数／原体験コンテンツ | 経営陣プロフィール、メディア掲載実績、経営者個人の発信 |
| people | カルチャー・人の可視化 | 社員インタビュー量／カルチャーの伝わり方 | メンバー紹介、カルチャー・制度、ブログ・note |
| reach | 認知・第三者評価 | ターゲットからの応募・返信率／事前認知 | 公式SNS、ニュース・プレス、OGP設定 |
| ops | 採用広報の運用・活用 | 担当・予算／選考でのコンテンツ活用 | 採用ページ、ATS・求人媒体、募集職種・カジュアル面談導線 |

### スコアの算出

- 観点スコア = 設問スコア × 70% + HPスコア × 30%（URL未入力・取得失敗時は設問のみ）
- 総合スコア = 5観点の平均。ランクは S(85+) / A(70+) / B(55+) / C(40+) / D
- 診断タイプ = 最も低い観点で決定（全観点70以上なら「採用ブランド確立型」）
- 提案 = スコア70未満の観点を低い順に最大3つ

## 起動方法

```bash
cd fastgrow-diagnosis
npm install
npm start            # http://localhost:3000
```

Node.js 20 以上が必要です。

### 環境変数

| 変数 | 説明 |
|---|---|
| `PORT` | 待ち受けポート（既定 3000） |
| `ANTHROPIC_API_KEY` | 設定するとClaudeによる総評（AIレビュー）が有効になります。未設定ならルールベース診断のみ |
| `CLAUDE_MODEL` | AIレビューに使うモデル（既定 `claude-opus-5-5`） |
| `AI_REVIEW=off` | APIキーがあってもAIレビューを無効化 |
| `LEAD_WEBHOOK_URL` | リード受信時にJSONをPOSTする先（Slack Incoming Webhook 等。`text` フィールドを含みます） |
| `ALLOW_PRIVATE_HOSTS=1` | **開発用**。localhost等へのHP取得を許可（本番では設定しないこと） |

## カスタマイズ

文言・設問・タイプ・提案メニュー・CTAはすべて [`public/config.js`](public/config.js) に集約しています。

- `BRAND.documentUrl` / `BRAND.privacyPolicyUrl`：媒体資料・プライバシーポリシーのURL（設定すると結果画面にリンクが出ます）
- `SOLUTIONS`：観点ごとの FastGrow 提案メニュー。**実際の商品名・内容に合わせて編集してください**（現在は汎用的な表現です）
- `QUESTIONS` / `AXIS_COMMENTS` / `TYPES` / `RANKS`：設問・コメント・タイプ・ランクの定義
- `WEIGHTS`：設問とHP分析の配合比率

HPのシグナル判定ロジックは [`lib/analyze-site.mjs`](lib/analyze-site.mjs) の `SIGNALS` で調整できます。

## 構成

```
server.mjs            HTTPサーバー（静的配信 / POST /api/analyze / POST /api/leads）
lib/fetch-site.mjs    外部HPの安全な取得（SSRF対策・リダイレクト追跡・文字コード判定）
lib/analyze-site.mjs  HTMLからのシグナル抽出とHPスコア算出
lib/ai-review.mjs     Claudeによる総評（構造化出力）
public/               フロントエンド（ビルド不要のES Modules）
test/                 node --test によるテスト
```

## 注意事項

- HP分析はサーバー側でHTMLを取得する静的解析です。JavaScriptで描画されるサイト（SPA）は本文がほとんど取れず、結果画面に「参考値」の注記が出ます。
- 内部ネットワーク宛て（プライベートIP・localhost・メタデータIP等）のURLや標準外ポートは取得しません。
- `/api/analyze` は1IPあたり10分10回、`/api/leads` は5回のレート制限があります（プロセス内メモリ）。
- リードはJSON Lines形式でローカルファイルに追記しています。本番運用ではCRM／スプレッドシート連携やDB保存への置き換えを推奨します。
